# Аудит сайта ТОВ БК Слава — 1 октября 2026

Проверен существующий сайт; визуальная концепция, украинские тексты, контакты и структура страниц сохранены. Работа выполнена в текущем проекте React 19 / TanStack Start / Vite, с проверкой локальной production-сборки в Chromium.

## Область проверки

Все 12 страниц: главная, каталог услуг, шесть страниц услуг, «Наші роботи», компания, контакты и приватность; отдельно — 404 и служебные ресурсы.

Размеры экрана: 320, 390, 600, 601, 768, 900, 1024, 1440 и 1920 px. Проверены header, desktop/mobile navigation, hero, блок 2006, каталог и изображения услуг, карусель, карточки и фильтры работ, сравнение до/после, CTA, консультация и footer. Дополнительно проверены клавиатура, открытие/закрытие окон, подписи и ошибки формы, альтернативные тексты изображений, focus/hover/active и WCAG A/AA через axe-core.

## Найденные проблемы и исправления

| Проблема | Исправление |
| --- | --- |
| Два слоя CSS с перекрытыми правилами старой концепции | Стили объединены в `app/src/styles.css`; удалены 339 перекрытых деклараций, правила неиспользуемых секций и отдельное подключение `redesign.css`. Порядок каскада сохранён. |
| Низкий контраст текста в footer, номеров услуг и подписей | Скорректированы второстепенные оттенки в пределах существующей зелёной палитры. |
| Бледная стрелка на светлом hero CTA | Стрелка наследует контрастный цвет текста кнопки. |
| Неочевидный текущий раздел навигации | Добавлены `aria-current`, видимое выделение текущего раздела и состояния клавиатурного фокуса. |
| Ошибки формы не связаны с полями, фокус не переходит к ошибке | Добавлены `aria-invalid`, `aria-describedby`, обязательность согласия и фокус на первом некорректном поле. |
| Телефон в примечании формы не отличается от обычного текста | Добавлено подчёркивание ссылки. |
| Возврат фокуса после закрытия окна отсутствует или указывает на удалённую кнопку | Сохраняется кнопка, открывшая окно; после закрытия фокус возвращается к CTA, карточке или кнопке меню. |
| При переходе из проекта в консультацию оставались два модальных окна | Карточка проекта закрывается перед консультацией; сохраняется возврат к исходной карточке. |
| Названия типов проектов не соответствуют вариантам формы | Проекты связаны с существующими услугами через slug; выбор в форме теперь всегда корректен. Публичные названия проектов сохранены. |
| Разные изображения одной работы на главной и в портфолио | Изображение берётся из единого источника данных; для первой работы сохранено изображение, уже использовавшееся в карусели. |
| Состояние карусели не пересчитывается при смене ширины | Добавлен ResizeObserver и единый расчёт позиции/границ; управление стрелками клавиатуры доступно при фокусе на карусели. |
| Избыточная загрузка больших изображений | `sizes` задаётся по роли изображения; полноширинные фото и изображения в окне проекта получают отдельные размеры. |
| Логотип 1,7 МБ загружается для маленького header/footer | Подготовлены прозрачные WebP: 144 px / 10 624 байта для header/footer и 720 px / 125 116 байт для страницы компании. Оригиналы сохранены. |
| Старые цвета браузерной темы и manifest | Цвета приведены к текущим токенам продукта. |
| При недоступном sessionStorage форма утверждала, что данные сохранены | Подготовка письма продолжает работать, а статус корректно сообщает, что данные доступны только в открытой форме. Обычный текст успешного сохранения сохранён. |
| Вступительное видео могло удерживать экран при зависшей загрузке | Таймер выхода запускается независимо от готовности видео. Блокировка прокрутки и Escape управляются существующим Dialog; закрытие сохраняет предусмотренную анимацию и возвращает фокус на main. |

## Что проверено и оставлено

Общая сетка, композиция hero и блока 2006, палитра, основные размеры заголовков, порядок секций, карточки и пропорции портфолио сохранены. Нет побайтовых дубликатов WebP. В шести карточках портфолио используются разные изображения. Повторение иллюстрации одной услуги в каталоге и на её странице оставлено как согласованное представление одного направления. Битые изображения и внутренние ссылки проверяются также автоматически.

Код поставляемых, но не используемых шаблонных компонентов не удалялся: они не импортируются страницами сайта и не требуют изменения для исправления публичного интерфейса. Новые пользовательские функции, отзывы и контент не добавлены.

Telegram username и Telegram-интеграция не изменялись. Форма сохраняет существующий сценарий подготовки обращения и передачи текста в почтовый клиент. Автоматическое серверное отправление заявок не входит в этот этап.

## Повторная проверка

Из каталога `app`, при работающей production-версии на `http://127.0.0.1:8080`:

```sh
bun run typecheck
bun run build
bun run start
```

В другом терминале:

```sh
bun run test:audit
```

В Windows PowerShell при запрете выполнения `.ps1` используйте `bun.cmd` вместо `bun`. На машине с малым запасом памяти TypeScript/Vite можно запускать через Bun: `bun.cmd --bun node_modules/typescript/bin/tsc --noEmit` и `bun.cmd --bun node_modules/vite/bin/vite.js build`.

`SITE_TEST_URL` позволяет проверить другой локальный адрес. JSON-отчёты и скриншоты сохраняются в `refs/audit-after/`; исходное состояние — в `refs/audit-before/`. Проверяются также формы с отключённым sessionStorage, отказ загрузки видео, служебные файлы, HTTP 404 и частичная загрузка видео.

Итоговые результаты фиксируются в `refs/audit-after/report.json`, `refs/audit-after/interaction-report.json` и `refs/audit-after/layout-report.json`.

## Дополнительный проход: узкие экраны и стабильность загрузки

- Увеличены подписи услуг, фильтры, хлебные крошки, примечания и текст footer, ранее имевшие размер 9–11 px, до 12 px. Основные заголовки и визуальная иерархия сохранены. Интервал контактных иконок footer уменьшен для экрана 320 px.
- Убран случайный focus-outline вокруг всего `main` после закрытия заставки. Фокус остаётся на правильном элементе; видимые рамки интерактивных элементов сохранены и проверяются отдельно.
- При замедленной загрузке шрифтов выявлен перенос хлебных крошек на страницах гипсокартона и сантехники при 320 px (CLS до 0,166). На экранах до 360 px название услуги теперь заранее размещается на отдельной строке, чтобы поздняя загрузка шрифта не сдвигала контент.
- Design inspector разрешён только в режиме разработки. Production-сборка проверена даже с установленным `HF_DESIGN_INSPECTOR=1`: служебный модуль в неё не попадает.
- Дополнительный тест проверяет 78 сочетаний страницы и viewport, включая 404, 320×568, 360×640, 390×844, 768×1024, 844×390 и 1440×900. Загрузка шрифтов задерживается на 1 секунду, изображений — на 400 мс. Измеряется CLS и проверяются элементы за пределами viewport, переполнение и debug/test-кнопки.

## Результат финальной проверки

- Production-сборка, TypeScript и ESLint для изменённого кода: успешно.
- 108 сочетаний страницы и ширины экрана: успешно, без горизонтального переполнения и битых изображений.
- 142 проверки основных взаимодействий и 66 дополнительных проверок: успешно.
- 18 внутренних ссылок: HTTP 200; отсутствующая страница: HTTP 404.
- Проверки axe-core страниц, меню, консультации, окна проекта, сравнения и 404: без найденных нарушений проверяемых правил WCAG A/AA.
- Малый логотип загружается вместо оригинала; reduced motion исключает загрузку вступительного видео.
- Проверены подготовка письма при запрещённом sessionStorage, мобильный/desktop источник видео, пропуск, однократный показ и автоматический выход при зависшей загрузке.

Локальная версия после аудита: <http://127.0.0.1:8080>. Публичный хостинг в рамках этой работы не перенастраивался. Проверки выполнены в Chromium; это не заявление о сертификации accessibility или тестировании всех браузеров и устройств.
